1. INTRODUCTION                                          *loupe-introduction*

Loupe is a bottom-docked fuzzy finder with a full-viewport live preview. It is
source-based: the source menu changes *what* is searched, while matching,
previewing and actions stay the same.

Browsing never opens a file buffer — files are read into a scratch buffer, and
only the choose actions create real buffers.

A freshly opened picker selects nothing, so the view behind it is left alone:
the preview appears once you move the selection, type a query or click a row.
Until then there is no selected row, and the choose actions do nothing.

The drawer is persistent: it is an ordinary bottom split that keeps its query,
selection and source while it does not have the cursor. `<Esc>` *parks* it —
the preview withdraws, the cursor returns to the editor and every ordinary
window command applies again. Focusing the drawer again (`<C-w>b`, `:Loupe`,
or the mapping that opened it) resumes filter mode over the same state, and
`<C-c>` closes it for good. Choosing a file parks it too (quickfix-style);
set `close_on_choose` (see |loupe-configuration|) for the classic "select and
it is gone" behaviour.

The preview belongs to filter mode: it is shown only while the drawer has the
cursor and a row is selected, so moving the cursor out of the drawer never
leaves a float covering the editor. Files are still only opened for real by
the choose actions.

Requires Neovim 0.11+ and the external tools `fd`, `rg` and `git` (each
optional; Loupe degrades gracefully). A Nerd Font is needed for the icons.

2. SETUP                                                       *loupe-setup*

>lua
    require("loupe").setup({
      default_source = "files",
      trash = true,
    })
<

`setup()` is optional; defaults apply if it is never called. See
|loupe-configuration|.

3. COMMANDS                                                 *loupe-commands*

:Loupe [source]         Open the picker, optionally on a specific source, e.g.
                        `:Loupe grep`, `:Loupe symbols`, `:Loupe buffers`. If a
                        picker already exists this focuses it: a parked drawer
                        keeps its state, and asking for the current source again
                        re-queries it from the cursor's current position.

While the drawer has the cursor, `<Esc>` parks it and `<C-c>` closes it. With
the cursor elsewhere the drawer is an ordinary window: `<C-w>b` (or `<C-w>j`
from the pane above) focuses it and restarts filter mode.

Loupe deliberately does not create any global keymaps. Suggested:

>lua
    vim.keymap.set("n", "<C-p>", function() require("loupe").open() end)
    vim.keymap.set("n", "<leader>fw", function()
      require("loupe").open({ source = "grep" })
    end)
    vim.keymap.set("n", "<leader>ss", function()
      require("loupe").open({ source = "doc_symbols" })
    end)
    vim.api.nvim_create_autocmd("LspAttach", {
      callback = function(ev)
        local o = { buffer = ev.buf }
        vim.keymap.set("n", "grr", function()
          require("loupe").open({ source = "references" })
        end, o)
        vim.keymap.set("n", "gri", function()
          require("loupe").open({ source = "implementations" })
        end, o)
      end,
    })
<

4. SOURCES                                                   *loupe-sources*

Switch sources with the source menu (`<C-o>`), or step along the tab strip
with `<C-Right>` and `<C-Left>`, which wrap at both ends.

  f  files           `fd` -> `rg` -> `git`     project files
  d  dirs            `fd`                      directories; <CR> descends
  b  buffers         builtin                   open buffers
  r  recent          frecency store            recently/frequently opened
  c  changed         `git status`              staged/unstaged/untracked
  g  grep            `rg` -> `git grep`        live content search
  s  symbols         LSP workspace/symbol      live
  t  doc_symbols     LSP textDocument/documentSymbol
  u  references      LSP textDocument/references
  i  implementations LSP textDocument/implementation
  e  diagnostics     vim.diagnostic

`grep` and `symbols` re-query on each keystroke (debounced); the preview jumps
to the match. Choosing a symbol or diagnostic jumps to its location.

`references` and `implementations` are cursor-relative: they ask the language
servers once for the symbol at the cursor where the picker was opened, then
fuzzy-filter the locations client-side like `doc_symbols`. They are the
fuzzy-search counterparts of the default `grr` and `gri` maps; rebind those
to `loupe.open()` to keep the muscle memory (see |loupe-commands|).
Re-invoking one of those mappings while the picker is parked focuses it and
re-queries it from the cursor's new position; focusing the drawer any other
way keeps the snapshot the picker was opened with.

A source that finds places rather than files draws them in two columns: what
was found on the left — the matched line, the symbol, the message — and where
it is on the right (`path:line`, or the symbol's kind for `doc_symbols`). A
grep hit is highlighted inside its line, as it is in the preview. Both
columns are searchable, but only the left one is highlighted as you type.

`grep` streams: matches appear as `rg` finds them and the search is stopped
once `max_results` have arrived (the title shows `N+`; `…` while running). A
new keystroke stops the running search before starting the next.

`files` and `dirs` are cached per root: reopening the picker shows the last
list immediately while a fresh enumeration replaces it in the background.

The drawer is laid out as a fixed viewport: the prompt on the first row and
one match per row after it. The window bar is the only chrome: it holds the
source tabs (the active one highlighted) prefixed by the key that switches
them, and on the right the current root, when browsing away from the project
root (`<BS>` on an empty query goes up, `<C-r>` returns).

The source menu takes over that strip rather than opening anything: `<C-o>`
marks each tab with its own key. The strip takes a lifted background while it
is open — a nudge from the list's, so nothing else about the row changes.

Labels do not move: a key that is the label's first letter is underlined
where it already is, and one that is not is appended (`Doc t`). An interior
letter is never marked, and neither is a shifted key. Any other key cancels,
which the strip says while it is lit. Rebinding `mappings.sources` changes the
keys shown.

The prompt shows the source glyph, the source name while the query is empty,
and the count on the right: `shown/total` for list sources, `found` for live
ones.

5. CONFIGURATION                                         *loupe-configuration*

`require("loupe").setup(opts)` deep-merges over the defaults. Every keybinding
is data; set a value to `false` to unbind. See `lua/loupe/config.lua` for the
full set.

>lua
    require("loupe").setup({
      height = function() return math.max(10, math.floor(vim.o.lines * 0.33)) end,
      max_results = 200,
      default_source = "files",
      root = function() ... end,
      backend = "ripgrep",          -- matcher engine: "ripgrep" | "fff"
      backends = { files = { "fd", "rg", "git" }, grep = { "rg", "git" } },
      preview = { enabled = true, max_lines = 2000, max_bytes = 1048576, diagnostics = true },
      icons = true,
      git = true,
      frecency = true,
      trash = true,
      close_on_choose = false,
      prompt = "> ",
      prompt_caret = "▏",
      mappings = { browse = { ... }, sources = { ... } },
    })
<

`preview.max_lines` and `preview.max_bytes` bound what is read into the
preview, so a file with one enormous line costs no more than a normal one.

Mappings are grouped by context: `browse` (the result list) and `sources`
(the `<C-o>` source menu). A `browse` value names a built-in action (`open`,
`down`, `split`, `page_up`, `park`, `close`, ...); a `sources` value names a
source. By default `<Esc>` is `park` and `<C-c>` is `close`. Keys may use any
notation Neovim understands (`<C-s>` == `<C-S>`); set a value to `false` to
unbind, and note that `<C-j>`/`<C-m>` resolve to `<NL>`/`<CR>`.

7. LUA API                                                       *loupe-api*

loupe.setup({opts})         Configure. See |loupe-configuration|.
loupe.open({opts})          Open. `opts.source` selects the initial source;
                            an existing picker is focused instead of rebuilt.
loupe.park()                Leave filter mode, keeping the drawer and state.
loupe.close()               Close for good.
loupe.toggle({opts})        Park when focused, focus or open otherwise.
loupe.is_active()           Whether a picker exists (focused or parked).
loupe.is_focused()          Whether the picker currently has the cursor.

While the drawer has the cursor, `<Esc>` parks it and `<C-c>` closes it;
both are ordinary mappings (see |loupe-configuration|) so either can be
rebound. Keys are read from inside a `:try` block, without which Neovim's
interrupt would abort the picker's key loop part-way and leave the drawer,
the preview and the hidden cursor behind.

8. HIGHLIGHTS                                             *loupe-highlights*

Every group is defined with `default = true` and linked to a standard group,
so a colourscheme applies without configuration. Override any of them:

>lua
    vim.api.nvim_set_hl(0, "LoupeSelection", { link = "CursorLine" })
<

  LoupeSelection      Visual              the selected row
  LoupeMatch          Search              matched characters
  LoupeDir            Comment             a path's parent directory
  LoupeMeta           LineNr              the right-hand metadata column
  LoupeMetaFlag       DiagnosticWarn      the modified-buffer marker
  LoupeTab            computed            an inactive source tab
  LoupeTabActive      Title               the active source tab
  LoupeTabSelect      computed            the strip while a menu is open
  LoupeTabSelectActive computed           the active tab while a menu is open
  LoupeTabSelectKey   computed            the key to press
  LoupePrompt         Title               the prompt prefix
  LoupePromptCaret    LoupePrompt         the caret
  LoupeGhost          Comment             the source name on an empty query
  LoupeCount          LineNr              the result count
  LoupeEmpty          Comment             the "no matches" line
  LoupeBorder         StatusLine          the window bar
  LoupeBorderNC       StatusLineNC        the window bar when parked
  LoupeDrawerNC       computed            the list while parked
  LoupeGitAdd         DiagnosticOk        git: added
  LoupeGitMod         DiagnosticWarn      git: modified
  LoupeGitDel         DiagnosticError     git: deleted or conflicted
  LoupeGitNew         DiagnosticHint      git: untracked
  LoupeGitRename      DiagnosticInfo      git: renamed or copied

The computed groups are measured against the surface each one is drawn on.
A mute goes against `LoupeBorder`, the window bar itself; a lift goes against
`Normal`, the list the bar borders. Measured against the wrong ground, a
colour either fades into its own background or lands on its neighbour's.

`LoupeTab` is `LoupeBorder`'s foreground muted 30% towards its background,
so an inactive tab recedes while staying legible — `Comment` is built to sit
at the edge of legibility, which is right for a hint and wrong for a label
meant to be read.

The three select groups light the strip up. Their background is `Normal`'s
lifted by 6% (darkened on a light theme), far enough that an open menu reads
as its own surface rather than as more list; their text comes up to
`LoupeBorder`'s full foreground, because a menu makes every entry on the
strip a live choice and nothing on it should still be receding. The key to
press is marked by weight and by sitting at `Normal`'s own brightness, so
the strip gains no colour the closed one did not have.

Themes with no foreground or background of their own on the bar, or none on
`Normal`, fall back to `Comment` and `CursorLine`. Set any group yourself to
take over.
